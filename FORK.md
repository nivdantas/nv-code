# NV-CODE fork

NV-CODE is T3 Code Nightly with bot rows, sidebar profiles, usage widgets, screenshot mode, the Tako Ink theme and its own branding. Keep the fork thin: new behavior goes in `apps/web/src/nv/` or `apps/desktop/src/nv/`, and upstream files get small hooks into it. `vp run nv:touchpoints` fails when an upstream file changes without being listed below.

## Layout

| Path                          | Holds                                                                                                   |
| ----------------------------- | ------------------------------------------------------------------------------------------------------- |
| `apps/web/src/nv/nvStore.ts`  | Profiles and bot choices, persisted under `nv-code:ui-state:v1`. Upstream's `uiStateStore` stays stock. |
| `apps/web/src/nv/bots/`       | Bot art, avatar, customize dialog, brief, row and menu helpers                                          |
| `apps/web/src/nv/profiles/`   | Profile tabs, color choice, scope helpers                                                               |
| `apps/web/src/nv/usage/`      | Usage widgets under the draft composer                                                                  |
| `apps/web/src/nv/screenshot/` | Screenshot mode, its store and palette command                                                          |
| `apps/web/src/nv/theme/`      | Tako Ink, the default theme; its CSS is generated by `scripts/nv-tako-ink.ts`                           |
| `apps/web/src/nv/nv.css`      | Fork styles, imported once from `index.css`                                                             |
| `apps/web/src/nv/brand.ts`    | `NV_APP_NAME`; the icon is `apps/web/public/nv-code-icon.png`                                           |
| `apps/web/src/nv/i18n/`       | NV-CODE translations, keyed by English source text                                                      |
| `apps/desktop/src/nv/`        | Data folder names, the move from pre-rename Nightshift folders, and the Keychain key copy               |
| `scripts/nv-*.ts`             | Fork tools: `i18n:nv`, `theme:nv`, `theme:nv:check`, `nv:touchpoints`, `nv:update`                      |

## Upstream touch points

Web hooks, each a few lines:

- `Sidebar.tsx` (profile scope, bot menu, tabs, dialog host), `SidebarThreadRow.tsx` (bot row layout), `SidebarChrome.tsx`, `threadActionMenu.logic.ts`, `useComposerSend.ts` (brief), `ChatView.tsx` (glow, widgets), `CommandPalette.tsx`, `appInit.tsx`, `__root.tsx`, `index.css`, `branding.ts`, `vite.config.ts`, `T3Wordmark.tsx` (re-exports the NV mark), `standalone-page.tsx`.
- Keybinding `screenshotMode.toggle`: `packages/contracts/src/keybindings.ts`, `packages/shared/src/keybindings.ts` and `KeybindingsSettings.logic.ts`. One profile test is appended to `Sidebar.browser.test.tsx`.
- Tako Ink as a built-in: `themePalette.ts` (reserved id and built-in list), `ThemeSettings.tsx` (theme cards), `CommandPaletteThemeItems.tsx`, and `apps/web/index.html` (first-launch default, boot palette, dark base). `src/nv/theme/takoInk.test.ts` fails if the boot palette drifts from the runtime one.
- Theme hooks, data attributes only: `ThreadDetailsSection.tsx` (`data-thread-details-section`), `ThreadDetailsUsage.tsx` (`data-usage-label`, `data-usage-track`, `data-usage-fill`, `data-usage-value`), `ProviderInstanceIcon.tsx` (`data-provider-driver`).

Branding outside the web app: `apps/web/index.html`, `manifest.webmanifest`, `nv-code-icon.png`, `nv-grain.png`, `apps/desktop/src/app/DesktopAssets.ts`, `DesktopEnvironment.ts` and `DesktopEnvironment.test.ts`, `DesktopStatePaths.ts`, `DesktopUserData.ts`, the DMG backgrounds `dmg-background-latest.svg` and `dmg-background-nightly.svg`, `scripts/build-desktop-artifact.ts` and `build-desktop-artifact.test.ts`, and the root `package.json` scripts. `apps/desktop/src/main.ts` calls the two first-launch steps in `apps/desktop/src/nv/`.

## Theme hooks

Tako Ink styles the app only through stable hooks, never Tailwind classes, SVG details or translated labels: `data-workspace-area`, `data-nv-draft`, `data-chat-provider-model-picker`, `data-provider-driver`, `data-thread-details-section`, `data-usage-*`, `data-sidebar-row="shelf:*"`, `data-right-panel-tab-list`, `data-active-tab`, `role="tab"`, `data-slot="scroll-area-thumb"`, `data-chat-width`. If upstream renames one, fix the hook, not the CSS. To change the theme, edit `scripts/nv-tako-ink.ts` and run `vp run theme:nv`. `vp run theme:nv:check` fails when the generated file is stale. `node scripts/nv-tako-ink.ts --json <file>` writes a theme file for stock T3 Code.

## Taking upstream updates

The `nv-code` branch is published, so take upstream by merging a nightly tag, not by rebasing.

For a fresh clone, add the remote with `git remote add upstream https://github.com/pingdotgg/t3code.git` and install dependencies with `vp i`.

1. Run `vp run nv:update check` to see whether a newer upstream tag is available.
2. From a clean NV-CODE branch, run `vp run nv:update` to merge the latest nightly. Pass a tag after the command to pick a specific nightly.
3. If Git finds conflicts outside the generated web catalogs, resolve and stage them, then run `vp run nv:update finish`. The command regenerates the web catalogs, applies NV-CODE translations, and checks translations, fork touch points, and the theme.
4. In `apps/web`, run `vp run typecheck` and `vp test run src/nv src/themeBoot.test.ts src/themePalette.test.ts src/components/Sidebar.browser.test.tsx`. In `apps/desktop`, run `vp test run src/nv`. Review the staged changes and finish the merge with `git commit --no-edit`.

Translate new NV-CODE strings in `apps/web/src/nv/i18n/translations.json`. Run `vp run i18n:generate` in `apps/web`, then `vp run i18n:nv` and `vp run i18n:check` from the root.

## Releasing

The app version stays the upstream nightly it is built on, so version checks against other T3 environments keep working. Only the tag adds `nv-`. A version with anything after `-nightly.YYYYMMDD.N` switches the build to the stable channel.

Run `vp run nv:update build` to build the Apple silicon DMG for the newest upstream nightly merged into the current branch. To include T3 Connect, supply the public build configuration before building. A fresh checkout can use `cp -n .env.example .env`. [T3 Connect setup](docs/operations/02_connect-setup.md#public-application-configuration)

```sh
export PATH="$HOME/.vite-plus/bin:$HOME/.cargo/bin:$PATH"
V=$(git tag --merged HEAD --sort=-version:refname --list 'v*-nightly.*' | head -n 1 | cut -c 2-)
vp run nv:update build
(cd release/nv-code && shasum -a 256 "NV-CODE-$V-arm64.dmg" > "NV-CODE-$V-arm64.dmg.sha256")
git tag -a "nv-v$V" -m "NV-CODE $V (macOS arm64)"
git push origin nv-code "nv-v$V"
gh release create "nv-v$V" -R nivdantas/nv-code release/nv-code/NV-CODE-$V-arm64.dmg*
```

Write the checksum from inside the output folder so `shasum -c` works where the DMG is downloaded. A second release on the same upstream nightly uses the tag `nv-v$V-r2` and keeps the version.
